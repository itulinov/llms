# Этап 06 - оргструктура и должности

## Архитектурный принцип

Go управляет операциями и правами доступа. PostgreSQL обеспечивает целостность кадровых связей, основную должность и историю. React отображает результат, не воспроизводя кадровую бизнес-логику на клиенте.

## Результат и границы

Организации → дерево подразделений → штатные единицы → закрепление сотрудников → основная должность → история. Используем существующую схему без миграции 005. Центры затрат, типовые должности, функциональные руководители, импорт и физическое удаление вне этапа. Дополнительные поля сохраняются.

## Карточки

- Организация: код, обязательное название, отображаемое название.
- Подразделение: код, название, родитель в той же организации, статус, признак расформирования, даты. Организацию после создания не менять.
- Запретить самого себя, потомка и родителя другой организации. Проверку и изменение выполнять атомарно под advisory lock.
- Штатная единица: код, название, статус, признак руководящей, даты существования. Подразделение после создания не менять. Создавать вакантной.
- Закрытие подразделения не изменяет вложенные подразделения, должности и сотрудников; закрытие должности не открепляет сотрудника. Показывать предупреждения.

## Кадровые операции

- Закреплять работающего сотрудника на вакантную active-должность; несколько должностей разрешены. Для замены явно открепить, затем закрепить.
- Кадровая дата необязательна, по умолчанию current_date БД. Проверять формат без новых ограничений относительно приёма, текущей даты или существования должности.
- Даты закрепления не редактировать общей формой.
- Основную выбирать из закреплённых, разрешить null. Дата смены основной — текущая дата БД.
- Автоосновная единственной должности, очистка основной, события и снимки — только существующие SQL-триггеры.
- История из collaborator_position_history: кадровая дата, created_at, снимки и event_seq DESC. Переименования не меняют прошлое.

## API и конкурентность

Все маршруты /api/admin защищены RequireAuth и RequireRole admin:
GET/POST orgs, GET/PUT orgs/{id}; GET/POST subdivisions, GET/PUT subdivisions/{id}; GET/POST positions, GET/PUT positions/{id}; POST positions/{id}/assign и /unassign; GET collaborators/{id}/positions; PUT collaborators/{id}/main-position; GET collaborators/{id}/position-history.

- Точный updated_at карточки без JS Date. Для assign/unassign версия должности и актуальная занятость; для main-position версия сотрудника и актуальная принадлежность. updated_at сотрудника не версия всех назначений.
- Общий advisory lock 2026111301; затем сотрудники по UUID, затем должности по UUID. Проверки повторять под блокировками.
- После SQL/триггеров повторно прочитать актуальные карточки и назначения внутри транзакции; ответ после commit.
- Списки должностей/истории: 25 по умолчанию, максимум 100, стабильная сортировка и согласованные items/total.
- Origin, JSON, UUID, названия, даты; 400 формат, 404 объект отсутствует, 409 конфликт/цикл/занятость, 503 БД.

## Интерфейс

Admin: три колонки организации → дерево подразделений → карточка и штатные единицы. При выборе должности справа её карточка. На мобильном последовательные экраны с возвратом. Карточка сотрудника дополнена должностями, основной и историей.

## Приёмка и поставка

- Создание/редактирование и сохранность дополнительных данных.
- Два перемещения А→Б и Б→А не создают цикл; два назначения на вакансию дают один успех и один 409.
- Единственная основная, несколько должностей, смена/снятие основной, открепление очищает ссылку; ответы после триггеров.
- История без дублей, кадровая дата отличается от времени записи, сортировка event_seq, старые снимки неизменны после переименования.
- Проверять updated_at реально изменённых карточек, увольнение отзывает доступ без открепления, закрытие сохраняет закрепление.
- Все endpoints запрещены employee. Go -race, изолированная PostgreSQL, сборка Admin, Firefox.
- Незакоммиченные изменения авторизации не включать. README, AGENTS.md, отдельный коммит и GitHub после локальных проверок.
- Перед рабочей поставкой backup и проверка восстановления. На Ubuntu PostgreSQL-тесты, Docker/Nginx и реальный сценарий в Firefox.
- Без PostgreSQL-проверок кадровых операций, конкурентности и снимков этап не завершён.
